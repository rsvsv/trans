# 译稿格式规范

目标：同一份 Markdown 既方便人读，也方便 AI 用最少的 token 读准，并且能被 `pdftrans.py check` 机械校验。
派给子代理时，直接在提示里写「遵守 `<SKILL_DIR>/references/output-spec.md` 与 `figure-spec.md`」。

示例以中文为目标语言；译成其他语言时，标签词改用目标语言（图 → Figure / 図 / Abb.，表 → Table / 表 / Tab.），其余规则不变。

---

## 1 文件

- 路径：`<文献文件夹>/<文献文件夹名>.<语言代码>.md`，如 `2025_Wang_矿化胶原支架.zh.md`、`….en.md`、`….ja.md`。
- **UTF-8 无 BOM，LF 换行**。
- 一篇一个文件，不按章节拆分。
- 除页码锚点 `<!-- pN -->` 外，不写 HTML；不用 base64 图片、外链图片、`<br>`。
- 不留任何占位符（`TODO`、`待译`、`<!--CONT-->` 等）。长文分批写入时，每批都以完整段落结尾。

## 2 YAML 卡片头（文件第一段）

```yaml
---
# 以下数值仅为格式示例，不是任何论文的真实数据
title: "通过氧化代谢调控实现感染性骨再生的多相矿化胶原支架"
title_orig: "Multiphase Mineralized Collagen Scaffold for Infected Bone Regeneration Through Oxidative Metabolism Modulation"
authors: "Wang Q, Li Z, et al."
venue: "Advanced Functional Materials"
year: 2025
doi: "10.1002/adfm.202500593"
type: "研究论文"
source_lang: "en"
target_lang: "zh"
pages: 20
figures: 8
tables: 0
references: 56
keywords: "感染性骨缺损（infected bone defect）；矿化胶原（mineralized collagen）；氧化磷酸化（OXPHOS）"
one_liner: "负载 CuS 的矿化胶原支架通过调控氧化磷酸化兼顾抗菌与成骨"
subject: "多相矿化胶原支架（mp-MCS）"
method: "体外细胞实验 + 大鼠颅骨缺损（非感染 / S. aureus 感染）"
key_result: "感染缺损 12 周新骨比例 61.33 ± 6.81% vs 对照 13.03 ± 2.51% [p9]；24 h 铜离子释放 50.81 ± 0.73%（pH 6.5）[p5]"
anchors: "checked"
# 以下来自工作区 _fields.md（有才写）
in_vivo: "①SD 大鼠（rat），雄性，颅骨缺损（calvarial defect）⌀5 mm ‖ 感染：无 ②SD 大鼠（rat），雄性，颅骨缺损（calvarial defect）⌀5 mm ‖ 感染：金黄色葡萄球菌（S. aureus），1 × 10⁷ CFU/mL 100 μL，造缺损后、植入前"
---
```

- **字符串值一律加双引号**，数字可以不加。论文标题里常有冒号，不加引号会被标准 YAML 解析器判为错误。值内的双引号写成 `\"`。一个字段只写一行。
- 必填：`title`、`title_orig`、`target_lang`。其余字段推荐填写，缺项直接省略该行（工作区字段除外，见 §2.1）。
- **卡片头在全文译完后再写**：这时已读完全文，字段最准。
- `keywords`：原文关键词照抄，写成「译名（Original）；…」。原文没有关键词时省略。
- `one_liner`：一句话说清"做了什么 + 结果"，中文不超过 40 字，英文不超过 25 词。
- `subject` / `method`：研究对象或系统、方法或实验设计，各不超过 120 字。
- `key_result`：1–3 个最关键的结果，用「；」分隔，**每条末尾标原文页码 `[pN]`**（跨页写 `[p9-10]`）。数字照抄原文正文或表格，`check` 会查这些数字（小数和两位以上整数）是否出现在该页（±1）；不能用从图上读出的数。
- `anchors`：由 `anchor` 命令写入（`checked` = 已按原文复核；`auto` = 原稿无锚点、由脚本推定），不用手写。
- 关键实体写成「中文（原文或缩写）」：菌种拉丁名、模型英文名、指标缩写。这样卡片用中文或英文都能被 `find --in cards` 检索到。
- 可以按学科**自行添加字段**，`cards` 会原样汇总；需要每篇都填、反复按它筛选的字段，写进工作区的 `_fields.md`（§2.1）。
- 旧字段名 `title_zh / title_en / journal` 仍被识别。

### 2.1 工作区字段表 `_fields.md`

放在工作区根目录（文献文件夹的上一级）。学科字段只在这里声明，技能本身不内置任何学科字段。格式是一张两列表，说明文字直接写给填写的模型看：

```markdown
# 本库卡片字段

| 字段 | 填写说明 |
|---|---|
| in_vivo | 本文自己做的每个体内模型写一条，用 ①②③ 编号。每条格式：`①种属/品系（英文），性别，部位与缺损尺寸，单/双侧 ‖ 感染：……`。「感染：」后面：人为接种了就写菌种（拉丁名）、菌株号、接种量与时机；没接种写「无」；原文没交代写「未报告」。没有体内实验时整个字段写「无」 |
| timepoints | 体内取材时间点，「；」分隔 |
```

分类字段（每篇只会是几个固定值之一，要按它精确筛选的）可以加第三列「取值」，列出允许的写法，用 `/` 分隔：

```markdown
| 字段 | 填写说明 | 取值 |
|---|---|---|
| animal | 本文自己做的体内实验用的动物，多种用「；」分隔 | 大鼠 / 小鼠 / 兔 / 犬 |
```

`check` 会报不在列表里的值（如写成「SD 大鼠」「rat」），「无」「未报告」总是允许，值后面可以加括号注释（「大鼠（SD）」）。取值列只用于分类字段；用 ①② 编号的结构化字段不检查取值。同义写法（rat、SD 大鼠）要能被检索到，写进工作区 `_glossary.md`，`find` 会自动扩词，不必另设别名列。

填写规则（所有学科通用）：

1. 只写**本文自己做的**。引言、讨论里转述的别人的工作不算；“以后将要做”的不算；讨论或补充材料里提到的本文初步验证**要算**。
2. 体外和体内分开；术后自发感染之类“不是人为施加”的情况，写「无（…，见说明）」；只涉及部分组别时写明是哪一组，如「无（对照组 2 只自发感染）」。
3. **读完全文确实没有写「无」；原文提到了却没交代细节写「未报告」；不能空着或删掉这一行**。“库里没有”和“漏填了”必须分得开。没通读全文就不能写「无」。
4. **一个对象的几个属性写在同一条里，不要拆成几个字段**。例如每个动物模型的感染情况写在该模型那一条的「‖ 感染：」后面，而不是另设一个 `infection` 字段靠顺序对应：模型在条目里也会用「；」，拆开后脚本对不上号（实测 8 篇里有 5 篇对不上）。
5. 通读全文再填，关键事实可能只在讨论里出现。不要从相邻描述推断原文没写的细节（例如用体外实验的菌株号补体内模型）；推断出来的写进说明并标「推断」。

`check` 会检查表里每个字段有没有填；说明里出现 ①、`‖ 标签：` 时，还会检查每条是否带编号、带该标签。字段建议不超过 6 个，只放“以后会反复按它筛文献”的项目。换一个学科就换一张表，例如深度学习方向可以写 `task / dataset / metrics`，临床研究方向可以写 `study_design / sample_size / follow_up`。

## 3 页眉信息块（YAML 之后、摘要之前）

```markdown
# 通过氧化代谢调控实现感染性骨再生的多相矿化胶原支架

**原文标题**：Multiphase Mineralized Collagen Scaffold for …

**出处**：*Advanced Functional Materials*, 2025, 35: 2500593（研究论文）

**DOI**：10.1002/adfm.202500593

**作者**：Qibo Wang, Zixin Li, …（保留原文姓名与顺序）

**单位**：1. …（保留原文）

**通讯作者**：…（姓名与邮箱保留原文）
```

- 出处、年份、卷期、DOI **只从原文第 1 页核实后填写**，不凭记忆。原文没有 DOI 就写「原文未标注」。
- 收稿/接收日期、资助、共同一作说明：原文有才写。

## 4 正文

- `#` 全文只有一个（译文标题）。`##` 对应原文一级节，`###` 二级节，`####` 三级节。**照搬原文的层级和编号**，不自造序号，不跳级。
- **页码锚点**：每页内容开始处单独一行写 `<!-- p3 -->`，前后空行。页码严格递增，每页都要有，纯图页和参考文献页也不例外。`check` 会靠它发现漏译的页，`find` / `brief` 靠它给出页码。
  - `<!-- p1 -->` 放在页眉信息块之后、摘要之前（文件里 YAML 头之后的第一行必须是 `# 标题`）。
  - 分页落在段落中间时，不拆段：**跨页段落算在它开始的那一页**，下一页的锚点放在这个段落之后。锚点只需精确到段落。因此两个锚点紧挨着、中间没有正文是正常的（续段页、纯图页）。
  - 锚点单独成行，不要写在段落、表格、列表项中间。
  - 译完后运行 `anchor`：脚本按段落里的数字、外文词和图号对照原文逐页复核，证据确凿时自动校正（两篇试译里模型手放的锚点约一成段落差一页，多出现在页首页尾）。
- **一段一行**：段内不换行。例外：单段超过 1500 字时，在句号处换行、**不加空行**（Markdown 渲染仍是一段；读文件工具一行超过约 2000 字会截断）。
- 原文是列表才用列表，不把段落改写成要点。
- 摘要后写一行 `**关键词**：译名（Original）；…`（原文有关键词时）。
- 原文的 back matter 都要保留：致谢、作者贡献、利益冲突、数据可用性、补充材料说明等。原文没有的不写。

## 5 图与图注

```markdown
![图 2](figures/fig02.png)

**图 2** 水凝胶的表征。(a) 可注射性的宏观照片。(b) SEM 图像，标尺 50 μm。(c) EDS 元素面扫。数据为均值 ± SD（n = 3）；\*p < 0.05，\*\*p < 0.01。
```

- 图放在**正文首次引用它的那一段之后**；同一段引用几张图就依次排列。不要把几张图都堆到长节的末尾。
- 图片下一行就是图注，以 `**图 N**` 开头，**整条图注写成一段**，分图说明在段内依次排列。
- 图注是**原图注的完整翻译**：分图、组别、n、误差棒、标尺、显著性符号一个都不能少，但也**不添加原图注里没有的内容**：图里印着的标尺、p 值、示意图里的说明文字，原图注没写就不写。补充说明见 `figure-spec.md` 的 detailed 档。`check` 会把每条图注里的数字和同号原图注逐条比对。
- 统计星号一律转义为 `\*`，避免被渲染成斜体。
- 正文里的 Fig. 2 / Figure 2a 统一写成「图 2」「图 2a」；补充图写「图 S1」；示意图写「方案 1」（`scheme01.png`）。
- `none` 档不放图片，只保留图注，并在图注末尾加「（图见原文第 N 页）」。

## 6 表

- 原文表格转成 Markdown 表，紧跟一行 `**表 N** …` 表注（放表上方或下方均可，与原文一致）。
- 数值、单位、符号照抄，不舍入、不换算。合并单元格的值在每格重复填写。
- 非常复杂、无法转写的表，用 `figures --tables` 渲染成 `table01.png` 插入，并在表注里说明「原表结构复杂，见图像」。
- 表脚注（a、b、*）放在表注之后，单独一段。

## 7 数字、单位、符号

- 数值、单位、p 值、n、均值 ± SD、浓度、倍数**照抄原文格式**。
- 上下标用 Unicode：`μg mL⁻¹`、`cm⁻²`、`10⁶`、`H₂O₂`、`Ca²⁺`。不用 LaTeX，除非原文是数学推导，此时用 `$…$`。**科学计数法的指数必须是上标**：`1 × 10⁶ CFU/mL`，不能写成 `1 × 106`（`check` 会报）。
- 引用标记写成 `[12]` 或 `[3,5–7]`，不用 `<sup>`。
- 化学式、基因（*RUNX2* 保留斜体）、蛋白、材料缩写、菌株名（*S. aureus*）保留原样。

## 8 术语

- 首次出现写成「引导骨再生（guided bone regeneration, GBR）」，之后只用译名或通行缩写。
- 同一概念全文只用一个译名。多篇或多代理协作时，共用工作区根目录下的 `_glossary.md`，格式为每行 `原文 | 译名`（也可以写成 Markdown 两列表；一格里的多个写法用 `/` 或 `、` 分开，括号里的原文和缩写也算）。`find` 会用它自动扩词：搜「骨髓炎」时同时搜 osteomyelitis，所以检索常用的术语值得收进去。
- 没有通行译名的新造词，保留原文并在首次出现处给出意译。

## 9 参考文献

```markdown
## 参考文献

1. Zhang M, Xu F, Cao J, et al. Bioact. Mater. 2024, 31, 368.
2. …
```

- 标题用目标语言（参考文献 / References / 参考文献）。
- **条数和编号与原文完全一致**，1..N 连续。原文是 `[1]`、`(1)` 还是 `1.`，统一写成 `1.`。`extract` 已把编号文献切好放在 `_work/refs.md`，直接使用：删掉开头的 `<!-- pdftrans… -->` 说明行，把缺号注释换成从 `source.txt` 补出的条目。
- 原文是作者-年份制（无编号）时，用 `- ` 无序列表，按原文顺序排列。
- 默认**条目保留原文**：信息完整、便于检索，也最省成本。用户要求时才把文献标题译成目标语言，作者、期刊、卷期页码仍保留原文。
- 文末可以加一节：

```markdown
## 引用本文

原文引用格式（保留原文）

> 本文为原文的翻译稿，仅供学习参考；原文版权归原出版方所有。
```

## 10 自检清单（交付前）

- [ ] 跑过 `anchor`，结果为 OK、已校正或已整理
- [ ] `check` 无 FAIL，WARN 均已确认（尤其是“原文中找不到的数字”和“丢了上标的 10 的幂”）
- [ ] YAML 头可解析，`title / title_orig / target_lang / one_liner / key_result` 已填（原文有关键词时还有 `keywords`），`key_result` 每条带 `[pN]`
- [ ] 工作区有 `_fields.md` 时，表里每个字段都已填（「无」「未报告」也算填了）
- [ ] 每页都有锚点；原文的每张图、每个表在译稿里都有图注、表注
- [ ] 参考文献条数与原文一致，`refs.md` 的说明行和缺号注释已清掉
- [ ] 标题、出处、DOI 与原文第 1 页一致
