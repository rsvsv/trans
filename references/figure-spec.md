# 图片规范

只回答一个问题：怎样出图，才能让读图的一方（人或多模态模型）一次看清图里的字、标尺和显著性符号，又不浪费 token。

---

## 1 读图预算：为什么按像素总量裁图

多模态模型读图时，会把超过上限的图片等比缩小，具体上限因模型而异。以常见公开文档为例：Claude 大约在长边超过 1568 px 或总量超过约 115 万像素时缩图；GPT-4o 类模型会先把图缩放到一定尺寸，再按 512 px 小块计费。也有客户端实测上限在 160 万像素左右。

由此推出三条结论，与具体模型无关：

1. **dpi 和文件大小都不重要，重要的是图内文字占画面的比例。** 页边和空白也会占用预算，所以紧裁是性价比最高的一步。
2. **按面积控制，而不是只按长边控制。** 脚本同时限制总像素（默认 1,150,000）和长边（默认 1568），这是大多数模型都不会再缩图的安全值。已知读图模型的上限更大时，可以调高：`--max-px 1600000 --max-side 2000`，或设环境变量 `PDFTRANS_MAX_PX / PDFTRANS_MAX_SIDE`。
3. **画布总面积固定时，拆图是唯一能把字变大的办法**（见第 4 节 detailed 档）。

`figures` / `render` 命令直接从 PDF 矢量源按预算重新渲染：小图会放大渲染，大图会降低分辨率，不经过"先导出再缩放"的二次损失。

## 2 硬规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | PNG、RGB、无损 | 不用 JPG（文字毛边、染色图偏色）；不用 base64 内嵌；不用 SVG |
| 2 | 紧裁 | 只保留图形内容和图内文字，不要页眉、页脚、正文和图注；脚本自动留约 8 px 白边 |
| 3 | 不超预算 | `check` 会对超出预算的图报 WARN |
| 4 | 完整 | 所有分图、坐标轴、图例、标尺、显著性标注都要在图内；显微图的标尺不能被裁掉 |
| 5 | 原样 | 不重绘、不修图、不在图上叠加译文；图内文字的解释写进图注 |
| 6 | 命名 | `fig01.png`、`figS01.png`（补充图）、`extfig01.png`、`scheme01.png`、`table01.png`；跨页续图用 `fig08_part2.png`；分图放大用 `fig03-c.png` |
| 7 | 引用一致 | `figures/` 里的每个文件都在译稿中被引用，译稿引用的每个文件都存在；`check` 会双向检查 |

## 3 三个档位

| 档位 | 何时用 | 产物 |
|---|---|---|
| `none` | 只要文字、模型不能看图、追求最快 | 不出图；图注照译，末尾加「（图见原文第 N 页）」 |
| `standard`（默认） | 一般翻译 | 每张图一个 PNG + 完整翻译的图注 |
| `detailed` | 用户要精读图、核对数据、做综述比较 | standard 的全部内容，加上第 4 节各项 |

## 4 detailed 档的附加内容

1. **分图放大**：分图多于 6 个、或成品图里最小字号明显看不清（热图数值、密集的显著性星号）时，对关键分图单独出图：
   `render "<PDF>" "<文献文件夹>" --page 7 --clip x0,y0,x1,y1 --name fig03-c`，放在整图下方，并写一行 `**图 3c（放大）**`。
2. **读图提示**：在图注后另起一段，以 `> 读图提示：` 开头，写纵轴物理量与单位、组别对应的颜色等。**只能使用原文正文或图上明确写出的信息**，并与图注本身分开，避免和译文混淆。
3. **数值表**：只收录原文正文、图上数据标签或表格**明确给出**的数值，写成 Markdown 表并注明出处页。**不允许从柱高、曲线估读数值。** 原文没给数值就不做表。
4. **核对记录**：`_work/figure_review.md` 记录每张图的页码、裁切框（来自 `manifest.json`）、分图清单、核对状态。

## 5 出图流程

1. `figures "<PDF>" "<文献文件夹>"`：自动定位并出全部图，生成 `_work/figures_overview_*.png`。
2. 看总览图（只用于核对裁切边界和分图是否齐全；小字是否清楚要逐张打开 PNG）。方括号里是定位方式，可信度从高到低：
   - `above` / `below`：图形紧挨图注，通常可直接使用；
   - `prev-page`：图在上一页、图注在本页顶部（Nature、Wiley 常见），需要核对；
   - `band`：没找到图形对象，取的是图注上方的空白带，**必须**核对；
   - `NOT FOUND`：需要手动出图。
3. 手动出图：`pages … --pages N --grid` 渲染带网格的页面（网格上的数字是 PDF 点坐标），读出图的左上角和右下角，再执行 `render … --page N --clip x0,y0,x1,y1 --name figNN`。手动结果会记入 manifest，之后重跑 `figures` 不会覆盖它（除非加 `--force`）。
4. 只重做某几张图：`figures … --only fig03,figS01`。
5. 不能看图的模型：`above` / `below` 的结果直接采用；其余几类在交付报告里列出来，请用户核对。

## 6 不要这样做

| 做法 | 后果 |
|---|---|
| 整页截图当配图 | 正文和空白吃掉像素预算，图里的字被压到看不清 |
| 直接导出 PDF 里嵌入的位图 | 常常缺少矢量叠加层（坐标轴、标注、分图字母），或者只是一个分图 |
| JPG 压缩 | 文字出现伪影，染色图颜色失真 |
| 从图上估读数值写进表格或正文 | 等于编造数据 |
| 在图上叠加中文、重绘 | 引入错误，丢失原始证据 |
